# Transfer Tests

Transfer tests are temporary validation artifacts, never visual references or starter templates. Generate them from `DESIGN.md`, compare them with the active `v11` product-neutral light or dark gallery, and retire them after their reusable findings have been promoted.

`platform-window-chrome-transfer-v1.html` checks the same neutral workspace in Windows and macOS window frames. It validates platform-owned outer corners, native-control safe regions, title identity alignment, and a continuous glass silhouette; it does not define fixed system-control measurements.

`window-identity-directions-v5.html` is the current decision artifact for application-shell selection. Across unrelated utility, export, research, editor, and canvas domains, it validates five structures: single-purpose utility, back stack, persistent workspace, menu-driven application, and responsive panel canvas. It also checks single-owner titles, logo-optional chrome, content-driven window proportions, title-bar actions placed against platform safe regions, macOS global-menu ownership, compact Windows menu integration, and panel selectors that appear only when responsive collapse hides real destinations. Versions `v1` through `v4` are preserved as exploration history and must not override the promoted rules in `DESIGN.md`.

`native-utility-quality-transfer-v1.html` validates the native quality pass in an unrelated audio-cleanup utility. It checks coherent optical scaling, a measured editor inside a stable field shell, non-selectable interface copy, bounded long labels, one shared select recipe, weighted segmented controls, a larger seek hit target with a compact play/pause action, content-sized asynchronous detail, quiet dividers, and a rounded complex preview whose backdrop is clipped without a dark outline. The browser artifact can demonstrate geometry and state transitions; pointer capture beyond the native window, wheel ownership, caret rasterization, and physical scale still require hands-on native verification.

`native-utility-quality-transfer-v2.html` extends that unrelated utility with the field-tested motion contract. It keeps coarse status and button feedback inside stable shells, gives each replaceable region one opacity owner, uses a bounded one-time busy beat, makes keyboard and reduced-motion segmented changes immediate, leaves direct range input uneased, and removes the profile selector when `?profiles=single` leaves only one meaningful choice. It also removes browser-only animated window-height interpolation so the example matches the native content-sized fallback.

The completed darkroom series now lives in `../archive/darkroom/`. Its final `v7` artifact records the approved solid dark canvas and neutral dark glass without cursor-following lighting. The entire series is archived and must not guide new interface work.
